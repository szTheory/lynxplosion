# Phase 7 Integration Advice

**Decision:** Add Suzy math as a private, instance-owned device with a small register API and one deterministic completion event. Keep `core/input.c` and its existing logical input behavior intact. The math device reports availability, provides side-effect-free reads, applies byte writes, exposes its next guest-tick deadline, completes at that deadline, and validates/encodes its own snapshot record. Keep the arithmetic device independent of bus ownership: it must not seize the CPU/video bus, clear page state, alter `cpu_ready_at`, or participate in sprite `SDONEACK`/`CPUSLEEP` behavior.

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| Private `suzy` math state and scheduled completion | Fits the existing timer/audio/video device pattern; one state per machine; same register source for CPU access and public mapped inspection; makes mid-operation snapshot and deterministic timing explicit | Adds a scheduler event and snapshot/digest record; both read/write adapters and copied test builds must be updated | New `core/suzy.c`/header plus `internal.h`, `machine.c`, `snapshot.c`, tests and three copied source lists — Risk: map drift, event-order or snapshot-reachability bugs | Rec for Phase 7's locked arithmetic/register scope |
| Inline math fields and arithmetic in `machine.c` | Fewer new symbols and no new module source | Mixes register semantics, operation progress and the bus loop; encourages separate implementations in opcode precheck, bus access and public inspection; harder to validate snapshots as one device | Concentrates changes in `machine.c`, `internal.h`, `snapshot.c` — Risk: diverging mapped reads/writes and partial refusal mutations | Rec only if the logic remains a genuinely tiny latch with no scheduled state |
| Full Suzy bus-master integration alongside math | Can support later sprite requests and grant arbitration in the same device family | Pulls sprites, grants, `SDONEACK`, `CPUSLEEP`, CPU readiness and bus-order evidence into this phase; obscures arithmetic completion and adds reachable ownership states | Broad scheduler/bus/snapshot/test changes — Risk: scope and timing claims expand beyond SMR-01..04 | Rec if a later approved phase brings sprite bus ownership into scope |

**Rationale:** The existing core already has the right seam: timer, audio and video own deterministic state and expose next-event/apply operations to `machine_advance`; snapshots serialize validated device candidates before an all-or-nothing apply. A private math device reuses that structure while honoring Phase 7's explicit split between math progress and sprite bus ownership. The public machine remains opaque, so adding private state does not require a public struct/API change; callers continue to allocate through `lynx_machine_size`/`lynx_machine_align`.

## Plan-critical integration details

- **Preserve the existing input adapter.** `$FC92` (`SPRSYS`), `$FCB0` (`JOYSTICK`) and `$FCB1` (`SWITCHES`) are currently handled by `lynx__input_*` against the logical input/video state. Keep that path and its bus-grant sampling edge. Route other newly supported Suzy registers through the new math device only after the hardware research fixes the exact register/mirror map. In `core/machine.c`, update `bus_opcode_peek`, `bus_request_available`, `bus_access`, and `lynx_read_cpu_memory` together. Share address decoding, but keep readable and writable checks distinct where the register contract is asymmetric. Public CPU-memory inspection must remain a two-pass, side-effect-free peek; raw `lynx_read_memory` stays raw RAM.
- **Keep math completion a non-owner event.** Add a Suzy next-deadline query and apply branch to `machine_advance` (`core/machine.c`, current event priorities in `core/internal.h`). A completion due at the same guest tick as a CPU-visible result/status read must be applied before that CPU access. It must not delay a grant already priced, claim the video bus, clear the CPU page latch, or feed host time into guest progress. Use bounded integer deadline arithmetic under the existing guest-time headroom. Document arithmetic correctness separately from the selected software completion-latency policy; no hardware-timing claim follows from shared-core repeatability.
- **Treat the snapshot and digest as format changes.** A new canonical Suzy record belongs in the `lynx_machine` state, `core/snapshot.c` fieldwise serializer, restore candidate validation, refusal-before-apply path, and `guest_state_digest_bytes`. Under the already approved compatibility policy, bump snapshot format 7 to 8 and reject format 7 as a version mismatch; update `core/internal.h`'s payload-size assertion and all stated offsets. Bump the digest domain from `lynxplosion.guest-state.v3` and document the appended/ordered record. Restore checks must reject impossible combinations of idle/busy flags, operands/results, and deadlines without changing any machine byte; positive tests must restore during an operation and prove source/restored continuation equality. Reset/load must clear all Suzy fields through `lynx__power_on`.
- **Repair the independent readers before expanding fixture behavior.** Update the white-box snapshot layout/version consumers in `tests/api/test_api.c` (including format-positive and old-format refusal cases) and the independent public-API parser in `tests/diag/test_diag.c` (`SNAP_FORMAT`, `SNAP_PAYLOAD_SIZE`, rehash/refusal controls). Update `docs/snapshot-video.md`, `docs/snapshot-audio.md`, and `docs/audio.md` where format 7, payload length, offsets or digest v3 are named. Review `tests/cpu/test_cpu_vectors.c` for any snapshot-derived hash/offset assumption; its payload sizing is currently symbolic. Public ABI header and symbol checks need no new public function or layout assertion if Suzy remains private; the existing ABI boundary permits additional `lynx__` symbols.
- **Keep source-built evidence reproducible and rights-bounded.** `scripts/build-suites.sh` currently builds/verifies `cpu`, `timers`, `audio`, and `audio2`; Phase 7 needs explicit `math`/`memio` producer records (pinned source/main hashes, `ca65`/`ld65`, linker layout, BLL/label identities, recipe hash and the pinned suite `LICENSE`/`NOTICE`). Extend the consumers in `tests/suites/test_public_suites.c`, `tests/suites/run.cmake`, `tests/suites/tests.cmake`, and `tests/inventory/fast.txt` with exact inventories and both CPU profiles. Preserve generated BLL/labels in invocation-owned scratch. Scoped arithmetic/register agreement must not silently become full SUZ-02, and timing rows remain visible even if strict comparison fails. No emulator GPL source, BIOS, commercial ROM, extra dependency, or new CI job is needed.

## Refusal and adversarial controls

- `tests/api/test_api.c::case_map_matrix`, `case_memory_peek_pure`, and `case_timer_unavailable` currently assume `$FC00` is unsupported. Those expectations need auditing as soon as the Suzy decoder grows. Keep map overrides and fixed `$FFF8`/`$FFF9` precedence, hidden-RAM non-fallback, unsupported single-address guest writes, and atomic multi-byte inspection failure. For a stable mixed-span atomicity proof independent of which Suzy registers become supported, set `MAPCTL=0x02` so `$FDFF` is mapped RAM and read the two-byte span `$FDFF..$FE00`; `$FE00` remains the unsupported ROM route. Require `LYNX_ERR_UNAVAILABLE` and unchanged output bytes. Replace the old guest write to `$FC00` with a guest write to `$FE00` to retain the generic unavailable-write/no-hidden-RAM-mutation control; if the finalized Suzy map still has an unimplemented `$FCxx` register, retain a separate Suzy-specific refusal at that exact address.
- `CMakeLists.txt` shares `LYNX_CORE_SOURCES` for normal and plain builds, but fault-control builds copy an explicit source list. Update `tests/audio/fault_controls.cmake`, `tests/timers/fault_controls.cmake`, and `tests/video/fault_controls.cmake` when adding `core/suzy.c`; otherwise normal builds can pass while mutation controls compile a different core. Keep the plain ABI-symbol gate, no-writable-global scan, no-float scan, both compiler environments, and exact registered inventory.
- The guest-visible write, public mapped peek, and snapshot restore should all exercise the same Suzy registers; assert that rejected writes leave state/guest progress at the documented refusal boundary. At the scheduler tie boundary, test same-tick CPU reads, coarse versus sliced advance, reset, independent instances, active-operation snapshots, and hostile forged deadlines. Compare fieldwise state/payload independently of host output metadata. Add a mutation control for each new critical invariant rather than assuming a passing math vector detects decoder, scheduling, or snapshot regressions.
- Product and evidence boundary: record source result counts and all timing observations, but do not label the arithmetic/register subset as full `SUZ-02`, do not close `EVD-02`, and keep physical qualification parked. No equipment, firmware, or rights decision is needed for this software-only integration.
