## Phase Goal (user story)

**As a** developer, **I want to** have the 65C02-class CPU execute under data-defined Lynx I and Lynx II profiles, proven by pinned per-opcode vectors, **so that** later device phases build on a CPU whose behaviour is checked per profile without either profile being adopted as baseline.

<objective>
Run the pinned vectors in the check for both defined profiles with an exact per-profile inventory (ROADMAP success criterion 1; CONTEXT "Vector sourcing, inventory and controls": asserted fields, exclusion rule, compare tiers, parser, exit codes, inventory files).

Purpose: CPU-01 evidence. Any CPU defect the vectors reveal is fixed in `core/cpu.c` or `core/cpu_profile.def` in this plan; the data is never edited.
Output: the strict reader, the runner, two committed inventories and two inventory rows.
</objective>
