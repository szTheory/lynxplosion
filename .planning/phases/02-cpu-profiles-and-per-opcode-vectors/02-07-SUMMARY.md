# Phase 2 Plan 07: Fixture programs and the pinned-assembler gate Summary

**Two project-authored programs, a terminating one with a cited hand-derived trace (consumed 525 ticks, stop undefined at PC $021B) and a never-ending seeded-RAM loop (255 ticks per iteration after a 70-tick prelude), now assemble from committed ca65 source with the pinned cc65 on every check and must equal their committed hex byte for byte.**

## Accomplishments

- **Task 1 (commit bec9fe7).** `sum-trap.s` and `churn-loop.s` carry the RESEARCH section 7 derivations as comment blocks: the per-instruction table (PC, cycles, cumulative ticks under flat5, register and RAM effect), the expected final state (consumed 525, stop undefined, PC $021B, A $0F, X $FF, Y $00, S $FD, P $34, RAM $0010=01 $0011=01 $0300=0F $01FC=11 $01FD=0F), the S2 edge expectations (advance 524 gives BUDGET with registers final; advance 520 stops before the last PLA cycle with A=0, S=$FC, PC=$021B), the churn-loop cycle accounting (51 cycles = 255 ticks per iteration, 70-tick prelude), its 325-tick hand check, the golden workload shape (4096 ticks = 15 iterations plus 201 ticks) and the note that the `08` operand of `LDY #$08` is the content-sensitivity target. The hex files, the linker config and both manifests are committed; `sh scripts/check-manifests.sh` reports 6 manifests and 11 fixture files covered.
- **Task 2 (commit 4f6311f).** `run_cpu_fixtures` in `scripts/check.sh` (step `cpu-fixtures` directly after `probe`) copies each source and the linker config into `build/toolchain/`, assembles with `ca65 --cpu 65SC02` and links with `ld65 -C raw-0200.cfg` under `env -i`, removes the intermediates and prints `cpu fixture sha256 <name> <hex>`. `tests/cmake/cpu_fixtures.cmake` decodes the committed hex text (drops `#` lines and whitespace, lowercases) and compares it with the binary; a missing binary says "run scripts/check.sh", a mismatch names both files, both lengths and the first differing byte offset. Two tests registered: `fixtures.cpu_asm` (both programs) and `fixtures.cpu_asm.self_test` (a scratch copy of churn-loop.hex with offset 3 changed from 08 to 09 must fail with `differs from`; run directly it reports "differs from ... at byte offset 3", so it fails for the intended reason).

## Derivation versus CPU

No disagreement to report: this plan does not run the machine against the expectations. The expected registers, RAM and ticks are carried over unchanged from the independent derivation in RESEARCH section 7 (datasheet cycle counts x 5 ticks under flat5). Plan 02-09 is the first place the CPU meets them; if it disagrees, investigate CPU bug versus derivation error and record the evidence there, never edit the expected values to pass. The transcription itself was checked: the pinned assembler reproduced the research byte strings and both SHA-256 values on the first assembly, so no transcription error existed in the `.s` files.

## Measured timings

- `sh scripts/check.sh`: 51 s wall (61 s user + 61 s system CPU, 240% CPU) on a lightly loaded host; 84 tests passed (82 before plus the 2 new). Gate cost: `toolchain` label 0.05 s of test time for 4 tests; the cpu-fixtures step is two assemble-and-link runs (well under a second).

## Deviations from Plan

None - plan executed exactly as written. Two small choices inside the plan's latitude: the `.s` files use `.setcpu "65SC02"` as well as the command-line `--cpu 65SC02`, and the gate takes a directory/comma-list interface (BINDIR, HEXDIR, NAMES) instead of per-file BIN/HEX arguments so that the plan's single test names `fixtures.cpu_asm` and `fixtures.cpu_asm.self_test` cover both programs.

One tooling note, not a deviation: a first attempt to clear a scratch directory with a glob removal after a `cd` was blocked by the harness safety check and did not run; assembly of the first test copy then used a scratchpad directory outside the repository with no removal.
