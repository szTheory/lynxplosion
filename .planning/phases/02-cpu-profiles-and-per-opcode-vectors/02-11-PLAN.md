## Phase Goal (user story)

**As a** developer, **I want to** have the 65C02-class CPU execute under data-defined Lynx I and Lynx II profiles, proven by pinned per-opcode vectors, **so that** later device phases build on a CPU whose behaviour is checked per profile without either profile being adopted as baseline.

<objective>
Close the phase with honest documentation (CONTEXT "Source honesty": every stand-in value tagged and every unverified behaviour listed), the full vector lane as throwaway verification (CONTEXT "Full lane": run at Phase 2 verification; "Specific Ideas": the full lane and the profile-diff spike run at verification), a pushed commit with a green CI run selected by its head SHA, and the AUTONOMY.md CI efficiency review.

Purpose: every requirement's evidence is recorded and reproducible; the Linux leg confirms the golden.
Output: README section, profile document, SKELETON.md pointer, recorded full-lane and CI results, and any measured CI change.
</objective>
