## Phase Goal (user story)

**As a** developer, **I want to** have the 65C02-class CPU execute under data-defined Lynx I and Lynx II profiles, proven by pinned per-opcode vectors, **so that** later device phases build on a CPU whose behaviour is checked per profile without either profile being adopted as baseline.

<objective>
Prove the vector gates in the failing direction (CONTEXT "Negative controls (EVD-05 style)"; ROADMAP criterion 2: a named-fault control that selects the wrong profile fails the bit-operation vectors) and finish the full lane (`scripts/vectors-full.sh run`).

Purpose: CPU-05 evidence and the controls that make CPU-01 trustworthy.
Output: runner fault and results flags, the control script, the pin lint, the full-lane run mode and ten inventory rows.
</objective>
