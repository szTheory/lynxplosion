## Phase Goal (user story)

**As a** developer, **I want to** have the 65C02-class CPU execute under data-defined Lynx I and Lynx II profiles, proven by pinned per-opcode vectors, **so that** later device phases build on a CPU whose behaviour is checked per profile without either profile being adopted as baseline.

<objective>
Prove the CPU behaviour through the public path that hosts use (ROADMAP criterion 2: per-instance selection and bit-op behaviour per profile; criterion 3: a non-default per-access cost changes consumed ticks without changing architectural results), add the runner profile flag (CONTEXT "Runner"), rename `api.skeleton` to `api.cpu_program` and add `det.profile_agreement` (CONTEXT "Re-baselining"), and extend `det.sensitivity_state` with every new field and the cost-model flip (CONTEXT: "det.sensitivity gains a cost-model flip"; the cost model is internal, so the flip is white-box in `det.sensitivity_state`).

Purpose: public-path evidence for CPU-02 and CPU-03 and the seam-agreement check that ties the vector evidence (internal seam) to the shipping machine.
Output: runner flag and note, six new or renamed tests, extended det checks.
</objective>
