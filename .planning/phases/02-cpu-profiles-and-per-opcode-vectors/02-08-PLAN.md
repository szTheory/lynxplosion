## Phase Goal (user story)

**As a** developer, **I want to** have the 65C02-class CPU execute under data-defined Lynx I and Lynx II profiles, proven by pinned per-opcode vectors, **so that** later device phases build on a CPU whose behaviour is checked per profile without either profile being adopted as baseline.

<objective>
Two behaviour-neutral preparations that keep the machine-switch plan (02-09) small enough to land atomically: the bus-side cost model (CONTEXT "Cost model": pure function over const tables, `flat5` PLACEHOLDER, internal `test_skew` for success criterion 3), and parameterised det gates so the switch changes only values in one file.

Purpose: CPU-03 pricing exists and is unit-tested before the machine uses it; the golden staying unchanged proves neutrality.
Output: `core/bus.h`, `core/bus.c`, cost checks in `cpu.cycles`, parameterised det scripts. No inventory change.
</objective>
