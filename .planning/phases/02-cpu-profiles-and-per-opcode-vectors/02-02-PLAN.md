## Phase Goal (user story)

**As a** developer, **I want to** have the 65C02-class CPU execute under data-defined Lynx I and Lynx II profiles, proven by pinned per-opcode vectors, **so that** later device phases build on a CPU whose behaviour is checked per profile without either profile being adopted as baseline.

<objective>
Prepare the record-keeping the committed vector data needs before it lands (plan 02-03): the startup-tier vocabulary (CONTEXT "Manifests/validation": fixture manifests and claims accept `startup_tier = none`, run manifests stay `A`, small `validate-kv.sh` change with a control), the Phase 2 exposure record rows (CONTEXT "Specific Ideas"), and the claim-template note for a later vector claim.

Purpose: the rights and evidence records stay ahead of the data; every new rule has a negative control.
Output: the `--startup-tiers` option, three extended control scripts, exposure-record rows, a template note. No new CTest name (controls extend existing self-tests), so `fast.txt` and the claim do not change.
</objective>
