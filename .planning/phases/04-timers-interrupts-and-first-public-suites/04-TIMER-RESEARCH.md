# Phase 4 Timer and IRQ Research Memo

**Researched:** 2026-11-10  
**Scope:** Hardware timer, interrupt, CPU sleep and bus-request behavior for Phase 4 discussion. This is one decision-cluster memo, not canonical phase context or planner research.  
**Confidence:** MEDIUM. The main observations come from the Epyx Handy specification in a current community-hosted HTML transcription. ## Recommendation

[REC/INFERENCE] Use the Phase 4 requirement’s single, instance-owned timer bank on the existing absolute 16 MHz master-tick clock. Derive the selected 1–64 microsecond clocks from a shared, serialized divider phase; represent each timer’s backup/current count, CTLA control state, CTLB DONE/clock/borrow observations and its documented link source. Treat the divider phase and tie ordering as a deterministic project policy, not as proven power-on phase accuracy. Epyx explicitly says slow-clock phases may be nondeterministic at reset and that first-use timer periods can vary by one source unit. [CITED: Epyx `System Reset/Power Up`, Mikey Reset Recovery; Epyx `10. Timers/Interrupts`, Timers; Epyx `7. Audio`, Audio Channel Specification]

Keep interrupt pending bits separate from timer interrupt-enable state. A pending bit survives until software clears it; an enabled timer is allowed to set its source bit. Feed the resulting IRQ level into the Phase 2 CPU sampling contract at the request’s poll stamp, after timer state has advanced to that stamp. Model CPUSLEEP as the existing CPU bus-request pause seam; wake when the hardware IRQ condition asserts even if the CPU I flag is set, while retaining the documented caveat that real Mikey sleep is broken unless Suzy owns the bus. [CITED: Epyx `Appendix 2: Interrupts and CPU Sleep`, Handy Interrupts and CPU Sleep; project CPU contract below]

The reviewed pages establish Timer 4’s UART-ready exception, but leave the timer6 link source, exact shared-divider phase relationships, CTLA reset-DONE edge ordering, any Lynx I/II split, and complete equal-tick event ordering unresolved. These are research gaps, not negative hardware claims. Keep Timer 4 distinct from expiry-driven timer IRQs. [CITED: Epyx `10. Timers/Interrupts`, Interrupts; Epyx `Appendix 3: Hardware Addresses`, Timers and Misc] [UNKNOWN: no rule for the unresolved details was found in the pages inspected]

## Source observations and planning consequences

| Area | Source observation | Planning consequence |
|---|---|---|
| Clock unit | Epyx describes a 16 MHz Lynx system clock and timer/audio source periods of 1, 2, 4, 8, 16, 32 and 64 µs. At 16 MHz, 1 µs is 16 master ticks. [CITED: Epyx `7. Audio`, More to Sound; Epyx `Appendix 3: Hardware Addresses`, Timers] | Keep guest time integer and tick-stamped. Treat every period conversion as source-backed; keep the initial phase policy explicitly unverified. |
| Timer bank | Eight 8-bit down counters have backup values and selectable source clocks; source value 7 means linked input. The chapter documents link groups `0 → 2 → 4` and `1 → 3 → 5 → 7 → audio 0 → audio 1 → audio 2 → audio 3 → 1`. A reload of one counter clocks the next linked counter. [CITED: Epyx `10. Timers/Interrupts`, Timers] | Implement explicit link edges and propagate a link event only on the documented preceding timer event. Do not assume all eight timers form one simple numerical chain. Timer 6 exists in the register map but is absent from the published link-group list. |
| Period and first use | Backup value `N` produces `N + 1` source units; zero is valid for a full source cycle. The first use after setting a timer may take between `N` and `N + 1` units; subsequent reload intervals are `N + 1`. [CITED: Epyx `10. Timers/Interrupts`, Timers] | Separate first-start phase from reload cadence. If the deterministic core chooses one phase, tests should name it as policy and include first-start boundary controls. |
| CTLA / CTLB | CTLA has interrupt enable at B7, reset Timer Done at B6, reload at B4, count at B3, and source select at B2:B0. CTLB exposes Timer Done, last clock, borrow-in and borrow-out; DONE sets on timeout and is reset with CTLA B6. [CITED: Epyx `Appendix 3: Hardware Addresses`, Timers] | Model all source-observable bits and preserve them in snapshots. Keep raw control writes and computed dynamic bits distinct. |
| DONE bug note | The Epyx known-variances list says “The Reset Timer Done bit is not a pulse” and “The Timer Done bit requires clearing in order to count.” [CITED: Epyx `14. System Reset/Power Up`, Known Variances From Anticipated Optimums] | DONE gating is a required test axis. The note does not define whether clearing is sampled on the control write, held as a level, or ordered before/after a same-tick borrow; do not silently choose a hardware claim. |
| IRQ pending and enable | FD80/INTRST and FD81/INTSET read the same status bits. A write to INTRST clears the selected bits; a write to INTSET sets them. The interrupt notes say pending bits can be polled independent of masking, and disabling an interrupt requires clearing the source enable; clearing pending too is needed to prevent an already-pending request. [CITED: Epyx `Appendix 3: Hardware Addresses`, Misc; Epyx `Appendix 2: Interrupts and CPU Sleep`, Handy Interrupts] | Keep source enable and pending latch as separate state. IRQ level derives from pending state according to the project contract; acknowledge only selected pending bits. Include write-one-set and write-one-clear behavior as distinct bus side effects. |
| Timer IRQ conditions | Seven timers can generate IRQ; Timer 4’s status is driven by UART receive/transmit readiness rather than Timer 4 expiry. A timer’s interrupt signal asserts at count zero on an attempted borrow even when control bits prevent the borrow itself, then waits until the current CPU cycle ends before interrupting. [CITED: Epyx `10. Timers/Interrupts`, Interrupts] | Do not generate Timer 4 IRQ from its countdown. Leave UART-owned status behavior explicitly unsupported/stubbed if UART is out of scope. Use the Phase 2 profile poll location for CPU acceptance, while recording exact timer-event ties as inferred ordering. |
| Timer/video/audio ownership | Timer 0 is the horizontal line counter; Timer 2 is the vertical line counter; Timer 4 supplies UART baud. Timer 7 links to audio channel 0, and the audio channels then cascade in a ring back to Timer 1. [CITED: Epyx `10. Timers/Interrupts`, Timer Utilization and Timers; Epyx `Appendix 3: Hardware Addresses`, Audio] | Keep the timer bank reusable by Phase 5 video and Phase 6 audio. Do not build a fixed 60 Hz frame assumption into Phase 4 timer state. |
| Shared hardware and register access | Epyx says timer and sound channels rotate through shared hardware; direct register accesses can wait as long as 1 µs. [CITED: Epyx `7. Audio`, direct Mikey access] | Treat channel-slot timing as a separate unresolved bus-timing concern. The existing `flat5` bus-cost model is explicitly a placeholder; do not turn it into a timer accuracy claim. |
| Sleep and bus request | A write of zero to FD91 resets the CPU bus-request flip-flop. Interrupts wake sleep even with I set; Suzy bus grant can also resume the CPU. The same spec says sleep does not work unless Suzy has the bus. [CITED: Epyx `Appendix 3: Hardware Addresses`, CPUSLEEP; Epyx `4. CPU/ROM`, CPU Sleep; Epyx `Appendix 1: System Bus Interplay`, CPU Bus Release/Request] | Keep sleep as a stopped CPU request, not a new 65C02 instruction or host pause. Implement interrupt wake for Phase 4 and keep Suzy wake deferred; do not claim battery-saving sleep or full Suzy arbitration. |

## Adversarial checks for planning

Create a small original fixture per behavior, use fresh machine state and exact tick budgets, and compare register/pending/CPU observations rather than only a shared-core digest. No public-suite expectations are duplicated here; the separate suite audit owns those.

1. **Divider and phase boundaries:** exercise all seven source periods, count `0`, count `1`, first start, reload, stop, and enable/disable changes immediately before and after a source edge. Add one-tick-before/on/after controls so a constant first phase cannot conceal off-by-one behavior.
2. **Link/carry:** test timer0→2 and timer2→4, timer1→3→5→7, and timer7→audio0 edge propagation; check no propagation on unrelated base ticks. Name timer6 linking as unresolved rather than passing a guessed value.
3. **DONE/reset-done:** observe timeout latching, clear via CTLA B6, DONE-gating behavior, reset-done held high across a timeout, and reload while DONE remains set. A fault that removes DONE gating must fail its intended case.
4. **IRQ pending/enable:** prove a disabled timer does not newly set its interrupt source; a previously pending bit remains visible after its enable is cleared; INTSET can force a bit; INTRST clears only selected bits; timer4 expiry does not masquerade as UART-ready.
5. **IRQ/CPU boundary:** generate pending IRQ before, at and after a profile POLL; cover I clear/set, in-flight cycle completion, and sleeping CPU wake while I is set. Verify an unacknowledged pending source remains asserted and can be accepted again after RTI according to the Phase 2 CPU rule.
6. **Minimal sleep and bus request:** CPUSLEEP stops further CPU request grants without advancing the CPU instruction stream; pending enabled interrupt wakes it; no Suzy wake is asserted until Suzy exists. A no-interrupt sleep remains paused within the caller’s bounded advance budget.
7. **Snapshot/reset/determinism:** serialize prescaler phase, all timer current/backup/control/dynamic state, IRQ pending state and CPU sleep/request state. Restore mid-count and mid-chain, then compare event trace and final state with uninterrupted execution; reset twice from fresh state and check the declared deterministic phase policy.
