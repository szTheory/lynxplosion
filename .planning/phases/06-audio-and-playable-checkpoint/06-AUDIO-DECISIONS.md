## Sound behavior and timing evidence

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| One shared, bounded Mikey timer/audio event graph; 40 kHz integer PCM (16 MHz / 400 ticks) and tick-stamped channel events | Matches Epyx's shared timer/audio clock and documented link path; keeps timer, channel, PCM, video and input observations on guest ticks; 40 kHz has an exact integer interval and avoids fractional-rate drift | Extends the currently acyclic timer links into the documented T1→T3→T5→T7→A0→A1→A2→A3→T1 ring; exact channel-slot/reset phase and PCM mix are not specified | `core/timer.c`, mapped bus reads/writes, `core/machine.c`, snapshot format, caller-owned API buffers and consumer; risk: zero-reload ring can loop at one tick and same-tick sample ordering can drift | Rec if the shared clock/link contract is primary; bound each same-tick channel visit and make any deferred ring pulse a named, snapshot-safe software policy |
| Separate four-channel audio state bridged to the existing timer bank by timestamped borrow/reload events; same 40 kHz integer PCM contract | Keeps LFSR, integrator and audio registers in a focused module; retains existing timer-only tests and source evidence as a distinct layer; bridge gives a clear seam for event tracing | The documented link graph enters and exits audio, so both banks need one total order and shared ring/cycle handling; splitting CTLB and timer state can expose stale same-tick reads | New audio module plus timer/audio bridge, mapped bus paths, machine scheduler, snapshot format, caller-owned API buffers and consumer; risk: cross-bank re-entrancy, lost/duplicated pulses and inconsistent restore | Rec if module ownership is more important than a single counter graph; require a bounded, deterministic bridge that preserves every pulse and common-tick snapshots |

**Rationale:** **Source observations:** Epyx's Handy specification, Chapter 7 Audio and Appendix 3, lists four reset-zero audio channels; each has an 8-bit counter and backup (`N+1` source edges), 1–64 μs prescalers plus “previous,” a 12-bit shifter, nine selectable taps at bits 11, 10, 7, 5, 4, 3, 2, 1, 0, inverted XOR feedback, integrate mode, signed 8-bit volume, and output clipping; Appendix 3 maps `$FD20–$FD27`, `$FD28–$FD2F`, `$FD30–$FD37`, `$FD38–$FD3F`, and `$FD50` route-disable bits. The timer chapter gives the full group-B ring. See [Epyx-derived Chapter 7 Audio](https://www.monlynx.de/lynx/lynx7.html) (including Craig Nelson's 1991 memo), [Appendix 3 register map](https://www.monlynx.de/lynx/hardware.html) and [Timer/Interrupt chapter](https://www.monlynx.de/lynx/lynx8.html); the [Atari Lynx Developer Wiki identifies the original scanned Handy Specifications](https://atarilynxdev.net/doku.php/lynx:doc:handy_specifications.pdf). **Independent software oracle:** the permitted MIT `lynx-tests` pin is commit `b583dc43d532d3c41563a6fa35420614fbcead89` (archive SHA-256 `a70edf382afa2e16fae7f46fb115fb8a9edec6a3850a00f51e9f075602fbab3e`); local hashes are `audio/tests.s` `7a83a139738f10bf374d6ffb1d2be9ccef76de9dc6c6b552a8d8896f48afa6f0`, `audio/main.c` `b2e2854a659bacd1e2870fa0d0dd3b20b4c05de408bb750dfeb57deaab60b18f`, `audio2/tests.s` `2fe682487678d67489ff80b82949eddf027fdbdeb54dd5e4109260ea9bf770d8`, and `audio2/main.c` `d740878818add728e8a14531e0509c7c4a2ce6d995e48a79390196e1faf29d03`. Its source exercises CTLB, one-shot/reload, integrate/clipping, LFSR seed/taps, hot changes, zero-volume progression, T7→A0, A0→A1→A2→A3 and A3→T1; it is a test oracle, not a hardware constant source. Neither suite names `MSTEREO`, so add original tests for all eight route-disable bits and both output sides. **Inference and recommendation:** model `$FD21` bits exactly as mapped and the `$FD25` B7 tap separately from its control bits; reuse counter/reload/DONE/borrow behavior with tests for CTLB low-nibble writes, but label the undocumented audio B3/status lifetime and manual borrow-in details as inherited software policy. The current `core/timer.c` stores eight counters, drains only an increasing-index graph, and refuses T1 link mode because audio3 is absent; `core/machine.c` applies timer work before video DMA, refresh and CPU grants. Audio must join that event order without changing `LEGACY_FLAT5`, `VIDEO_POLICY1`, fixed-zero timer phase, the pending timer-14 disagreements, or the default `none` profile. **Unknowns:** exact audio first-edge/reset-divider phase, shift/update order where the notes do not settle it, temporal propagation rate around the link ring, signed integrator-to-DAC/mix normalization, the PWM low-pass (the same chapter says 4 kHz and about 4.5 kHz), and which physical revisions implement stereo; represent these as explicit versioned software policy or leave them unclaimed. For samples, use `S16` interleaved L/R PCM at a rational 40,000/1 Hz lattice (400 master ticks/sample), plus guest-tick channel events in caller-owned bounded buffers. This rate is an API choice, not a hardware constant; it preserves exact guest-clock cadence and avoids fractional drift with lower sample/capture volume than 50 kHz. Normalize/mix with explicit integer policy; sample after audio channel/link work at T and before a CPU grant at T, and leave a sample at the half-open target pending. Add original tests for reset/all four channel blocks, single-tap and multi-tap LFSR, signed extremes and integrator rails, count-zero reload, each link edge and bounded cycle, every MSTEREO bit, sample/event boundaries, sliced versus unsliced advancement, reset/load/two-instance isolation and snapshot continuation. Seed named faults (wrong tap map, dropped A3→T1 pulse, inverted stereo bit, 399/401-tick sample interval, missing serialized phase); each must fail its intended semantic assertion and pass with the clean core. Keep audio events and input/video/tick progress separate; the public-API consumer writes WAV beside the Phase 5 PPM. Keep the throughput baseline output-digest-bound and do not optimize before measuring. Use only the existing pinned MIT source and notice; add no dependency or rights-bearing content, open no emulator implementation source, change no LibFuturo contract, and preserve the no-firmware, no-physical-test and no-release limits. No new owner decision is needed for this scoped digital contract; O1/O5/O6/O9 remain open.
