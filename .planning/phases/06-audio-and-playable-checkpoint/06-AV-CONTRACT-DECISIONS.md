## Native PCM, Events and A/V Checkpoint

| Option | Pros | Cons | Complexity | Recommendation |
|--------|------|------|------------|----------------|
| Fixed 48,000 Hz stereo signed-16 PCM; return PCM, ordered channel events, progress, and any completed raw frame in caller-owned spans from one bounded A/V advance | Integer WAV sample rate, carries stereo mute behavior, exact clock ratio of 3 samples per 1,000 guest ticks, sample ordinal gives exact rational time without floating point or rounded tick labels | Sample instants fall on a 1,000/3-tick rational grid; output boundary and same-tick event ordering must be documented; no asynchronous decoupling | Public config/identity and A/V result/spans, audio snapshot state and format bump, consumer and API tests -- Risk: phase/boundary errors or an incomplete caller span | Rec if portable WAV output and one aligned A/V replay path are the v1 priority |
| Fixed 32,000 Hz stereo signed-16 PCM; same per-advance spans | Exact 500 guest ticks per sample, simpler phase and sample-time reasoning, integer WAV rate and same stereo semantics | Lower sample bandwidth than 48 kHz, does not directly match 44.1/48 kHz consumers without host conversion, rate is still an observation policy rather than a hardware fact | Same API and snapshot surface with simpler sample cadence -- Risk: treating a convenient divisor as Lynx hardware output rate | Rec if integer-tick sample instants matter more than host-rate compatibility |
| Fixed-rate core FIFO with explicit host read cursor (48 kHz or 32 kHz) | Host can advance independently of when its writer consumes output, natural batching for asynchronous consumers | Bounded FIFO fills and must back-pressure before guest mutation; restore must coordinate unread records with guest state and host cursor; larger machine/snapshot surface | Core queue, read API, overflow/refusal path, snapshot/checkpoint rules and tests -- Risk: dropped, duplicated, or replayed observations at overflow/restore boundaries | Rec if a later host needs asynchronous audio delivery and accepts queue/back-pressure complexity |

**Rationale:** Observed project contracts already favor bounded caller-owned spans with whole-call capacity/refusal checks, guest-tick metadata, immutable policy identity, versioned fieldwise snapshots, and host-owned replay cursors: see [the public API](../../../include/lynxplosion.h), [snapshot/video contract](../../../docs/snapshot-video.md), and [input replay contract](../../../docs/input-replay.md). The current frame-only replay keeps the canonical `LYNX-INPUT 1` file, captures raw frames and PPMs, and publishes a complete new output directory exclusively; the diagnostic WAV is still placeholder 8 kHz mono signed-16. Inference: use one fixed 48 kHz stereo signed-16 observation policy and one new bounded A/V advance result that emits the samples/events for that call and any completed frame, rather than retaining a core FIFO. Represent PCM time by absolute sample ordinal and the exact mapping `sample_index * 16,000,000 / 48,000 = sample_index * 1,000/3 guest ticks`; channel changes stay integer-tick events with deterministic same-tick ordering, so no rounded sample tick is misrepresented as exact. Keep audio channel state in guest snapshots/state digests, keep stream-file offsets and replay cursors in the host checkpoint (timeline digest, guest tick, pre/post input-edge phase, input index/mask, next sample ordinal, event-output offset, and already-published prefix identity), and include the immutable audio output policy in config/identity and the new snapshot format. Preserve `PROFILE_NONE`, default `LEGACY_FLAT5`, the Phase 5 input-only `consumer.frame_tracer`/`--mode frames` contract, and all existing source-oracle rows; add a separate source-built A-triggered sound-and-image fixture and `--mode av-replay` package with a manifest, per-frame raw/PPM outputs, ordered event records, and `audio.wav`. Automated checks can validate RIFF/WAVE PCM fields, block alignment, payload length and digest; check that released versus pressed input produces the fixture's documented guest marker, audio events, non-silent/different PCM, and responsive raw/rendered frames; and compare full PCM/event/frame suffixes across fresh, uninterrupted, and pre/post-edge snapshot restores while asserting contiguous sample ordinals and atomic capacity refusals. These checks establish software response and repeatability without speaker playback or physical hardware. Microsoft documents the integer per-channel sample-rate field and PCM block-alignment relation used by this WAV contract in [WAVEFORMATEX](https://learn.microsoft.com/en-us/windows/win32/api/mmreg/ns-mmreg-waveformatex) and [RIFF](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-). Unknowns remain hardware output-rate/mixing/pan fidelity and Lynx II stereo behavior; the selected rate and integer PCM are project observation policy, not qualification or a decision about a shared LibFuturo contract.
