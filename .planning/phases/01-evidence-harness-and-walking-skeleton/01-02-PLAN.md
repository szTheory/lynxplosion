## Phase Goal (user story)

**As a** developer, **I want to** run one command that builds the core and enforces the rights and determinism boundaries, **so that** I have proof that a skeleton machine is repeatable and refuses bad input without side effects.

<objective>
Give every run an identity: the core computes the SHA-256 of loaded content and reports it with the profile, RAM power-on policy and seed (API-04 run identity, DET-04 content identity), and the build identity (git revision, dirty flag, compiler, system) is baked in at configure time (DET-04 core build identity, RESEARCH Pattern 8). The SHA-256 unit is proven against standard vectors.

Purpose: the runner bundle (plan 01-03) and the snapshot header (plan 01-07) both need content and build identity from the core. RESEARCH open question 1 (F4) is resolved here: one SHA-256 unit lives in `core/`, shared with the runner; no public `lynx_sha256()` utility.
Output: `core/sha256.{c,h}`, `core/build_id.c.in`, `lynx_get_identity`, `lynx_build_id`, and three tests.
</objective>
