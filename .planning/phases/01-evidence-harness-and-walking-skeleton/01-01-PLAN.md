   - `lynx_machine_init`: refuse NULL `mem`, `cfg` or `out`; a `size` below `sizeof(struct lynx_machine)`; `mem` not aligned to `_Alignof(struct lynx_machine)`; `cfg->struct_size != sizeof(lynx_config)`; `cfg->profile != LYNX_PROFILE_NONE`; an unknown `ram_policy`; and `reserved != 0`.    - `lynx__power_on`: fill RAM per policy (policy 0 all `0x00`; policy 1 SplitMix64 with the state starting at `ram_seed`, 8 bytes per output, little-endian, from address 0). Copy SplitMix64 (Vigna, public domain) with its state taken by pointer, never a static. Zero all registers, `halted`, `guest_ticks` and the content fields.
   - `lynx_machine_deinit`: if the magic is valid, set `magic = 0` (poison). Deinit of an already-poisoned or NULL machine is a no-op.
   - `lynx_load_ram_image`: refuse a NULL machine or bad magic (`LYNX_ERR_ARGUMENT` / `LYNX_ERR_STATE`), NULL `bytes`, `len == 0`, `len > LYNX_ADDRESS_SPACE`, `load_addr >= LYNX_ADDRESS_SPACE`, and `len > LYNX_ADDRESS_SPACE - load_addr` (subtraction form, Pitfall 9). Every check completes before any write. On accept: call `lynx__power_on`, copy the bytes, set `pc = load_addr`, and set `has_content = 1` with `content_addr` and `content_len`.
   - `lynx__skeleton_step` (PROVISIONAL, marked in a comment as replaced by the Phase 2 CPU): if `ram[pc] == 0xDB`, set `halted = 1` and return. Otherwise `b = ram[pc]`; `a = (uint8_t)(a + b)`; `x = (uint8_t)(x ^ a)`; `y = (uint8_t)(y + 1)`; `ram[0x0100u + s] = a`; `s = (uint8_t)(s - 1)`. Then advance the PC with 32-bit arithmetic so an image that ends exactly at `0x10000` wraps correctly: `next = (uint32_t)pc + 1u`; if `next >= content_addr + content_len` (both `uint32_t`, the sum is at most `0x10000`) then `next = content_addr`; `pc = (uint16_t)next`. Never compare the 16-bit `pc` against the 32-bit end directly (it would wrap to 0 and leave the content range).
   - `lynx__budget_steps(guest, budget)`: returns `min(budget, UINT64_MAX - guest) / LYNX__TICKS_PER_STEP`, so guest time never wraps.
   - `lynx_advance`: refuse NULL `m`, `consumed` or `stop` with no state change; bad magic gives `LYNX_ERR_STATE`; no content gives `LYNX_ERR_STATE`. If already halted, set `*consumed = 0` and `*stop = LYNX_STOP_HALT`. Otherwise run up to `lynx__budget_steps` steps, adding 4 to `guest_ticks` per completed step. Stop with `LYNX_STOP_HALT` when a step halts (the halting check consumes no ticks), else `LYNX_STOP_BUDGET`. `*consumed` is the sum of ticks for completed steps and is always at most `budget`.
   - Inspect functions take `const lynx_machine *` and write only to their out parameters. `lynx_read_register` returns `LYNX_ERR_RANGE` for `reg >= LYNX_REG_COUNT`. `lynx_read_memory` refuses `len == 0` (`LYNX_ERR_ARGUMENT`), `addr >= LYNX_ADDRESS_SPACE`, and `len > LYNX_ADDRESS_SPACE - addr` (`LYNX_ERR_RANGE`).
